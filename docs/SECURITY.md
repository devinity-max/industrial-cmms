# Security and operational safety gates

| Risk | Required control | Evidence |
|---|---|---|
| QR copied or identifiers guessed | QR only opaque stable locator, authentication before any asset data, server scope checks | unauthenticated and cross-scope API tests |
| Viewer writes or admin outside scope | deny-by-default RLS and mutation checks, no privileged browser keys | direct API/RPC tests, not just UI |
| Credential abuse | provisioned individual accounts, managed password auth, rate limiting, MFA for privileged accounts before production, secure reset, revoke sessions on disable | brute-force/config review and stale-session test |
| Privilege escalation | restricted role provisioning; ignore self-editable metadata, check active membership on requests; inspect all functions and storage policies | self-escalation tests |
| Corruption/duplicate saves | validation, transactions, optimistic version, idempotency key scoped to actor/operation, history and audit | concurrency and lost-response tests |
| Malicious attachment | private buckets, authorization on reads and uploads, file size/content limits, malware scanning or quarantine before availability | unauthorized download, disguised file tests |
| Data exposure | HTTPS, restrictive CORS, CSP, no caching sensitive payloads, no secrets/logging confidential data, secure session handling and XSS review | deployment config and security review |
| Job/provider failure | persistent outbox, retries, deduplication, heartbeat, no secrets in messages | failure and retry tests |
| Data loss | separate DB and object backups, restore rehearsal, encrypted restricted storage and agreed RPO/RTO | restore evidence including attachments |
| AI/third-party data leakage | synthetic data only unless written authorization, no raw documents or credentials in prompts/repo | human review |

Production additionally requires company-owned approved domain/accounts, environment separation, controlled deployment identity, dependency/vulnerability review, independent qualified security assessment and remediation, monitoring/on-call responsibilities, data export/exit plan, maintenance and IT approval. No claims of absolute security. Authentication mechanism, MFA and session lifetime subject to IT policy. Do not build custom cryptography. Do not enable offline caching or service worker for confidential records in demo. Never use third-party QR URLs for permanent labels. Physical labels placed by authorized staff outside hazardous areas. No OT integration or operating instructions generated by this system.

Incident response: disable affected access/credentials, stop suspect deployment or jobs, preserve evidence, notify agreed company incident owner, assess exposure, restore/redeploy from known-good state, record corrective actions. Agree retention and lawful handling with company. No production secrets in issue trackers or agent transcripts.

Cloud development: use separate project identities and credentials, no real company records in dev. Restrict administrative dashboard access, use individual accounts and MFA, keep server secrets out of browser bundles and agent prompts. No remote resets. Only Developer A applies approved reviewed migrations; validate the target before each mutation.
